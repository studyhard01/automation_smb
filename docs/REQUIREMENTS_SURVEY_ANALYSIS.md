# 문서봇 요구사항 설문 분석

## 1. 문서 목적

`문서봇(Document Bot) 요구사항 조사 (응답).xlsx`의 응답을 기능 우선순위, 파일 포맷 지원 순서,
답변 방식, 문서 갱신·권한 요구로 다시 정리했다. 이 문서는 현재 합성 데이터 기반 기능 검증의 작업 순서를 정하는
근거이며, 실제 의료 문서 사용 승인을 의미하지 않는다.

분석 시 타임스탬프·이메일·작성자 성명은 집계에서 제외했다.

## 2. 조사 범위와 해석 한계

| 항목 | 확인 결과 |
|---|---|
| 응답 수 | 5명 |
| 응답자 소속 | AI연구소 5명 |
| 원본 구조 | 1개 시트, 46개 문항 열 |
| 해석 단위 | 1명 = 20%이므로 비율보다 `응답자 수/5명`을 우선 표기 |

이 결과는 표본이 작고 단일 소속의 의견만 포함한다. 따라서 전사 또는 분자유전팀 전체의 확정 요구사항이 아니라
**현재 제품 가설의 우선순위**로 사용해야 한다. 파일 포맷 응답도 실제 공유폴더의 파일 수를 센 결과가 아니라
응답자가 필요하다고 판단한 포맷이다.

또한 일부 기능은 `필수`로 선택됐지만 예상 빈도는 `사용 안 함/미정`이거나 미응답이었다. 이 경우 필수 여부는
중요도·품질 조건, 빈도는 직접 사용 횟수로 분리해 해석했다.

## 3. 결론 요약

1. **사용자 기능 중 최우선은 키워드 기반 단순 검색이다.** 5명 모두 필수로 선택했고, 예상 사용 빈도도
   매일 4명·주 1~3회 1명으로 가장 분명하다.
2. **문서 기반 Q&A, 문서 요약, 버전 관리도 5명 모두 필수다.** Q&A와 요약은 5명 모두 주 1회 이상 사용할
   것으로 답했다. 버전 관리는 사용 횟수와 별개로 잘못된 구버전 답변을 막는 정확성 조건으로 봐야 한다.
3. **저장소 등록·수집은 4명 필수·1명 보류지만 기술적으로 가장 먼저 필요하다.** 사용자에게 가장 먼저 보일 기능은
   검색이지만, 구현 순서는 수집·인덱싱이 앞선다.
4. **첫 포맷 묶음은 PPT/PPTX, XLS/XLSX, TXT/MD다.** 세 포맷군 모두 5명 전원이 필수로 선택했다.
   그다음은 PDF, DOC/DOCX, CSV/TSV로 각각 4명이 필수로 선택했다.
5. **답변 기본형은 `핵심 요약 + 상세 설명`이어야 한다.** 5명 모두 선택했다. 원문 링크/경로, 문서별 요약,
   단계별 절차는 각각 3명이 선택했다.
6. **근거가 없을 때 임의 답변하면 안 된다.** 응답은 근거 부족 고지 2명, 재질문 2명, 관련 문서만 제시 1명으로
   갈렸지만 공통 방향은 추정 답변을 피하는 것이다.
7. **현재 기능 테스트와 실제 문서 운영 준비를 분리해야 한다.** 역할별 범위 구분은 4명이 전부 또는 일부 필요하다고
   답했다. 현재 합성 데이터 테스트에서는 별도 보안 gate를 두지 않되, 실제 문서를 연결하기 전에는 접근 범위와
   민감정보 처리 정책을 확정해야 한다.

### 3.1 설문 이후 확정된 UI 결정

아래 항목은 설문 집계가 아니라 2026-07-30에 제품 방향으로 추가 확정된 사항이다. 설문 결과와 충돌할 때는
사용자에게 노출하는 화면 구성에 한해 이 결정을 우선한다.

#### 채팅 입력 영역

- 채팅 입력 영역의 `+` 요소를 제거한다.
- 파일 선택·첨부는 `파일 첨부` 버튼 한 곳에서만 제공한다.
- 같은 기능으로 예상되는 진입점을 중복 노출하지 않아 사용자의 혼동을 줄인다.

#### `사용할 기능` 선택 항목

| 구분 | 항목 |
|---|---|
| 제거 | 폴더 이름으로 찾기 |
| 제거 | 파일 내용에서 찾기 |
| 추가 | 문서 요약 |
| 추가 | 문서 기반 QnA |
| 추가 | 파일 버전 확인 |
| 추가 | 보고서 작성 |

`폴더 이름으로 찾기`와 `파일 내용에서 찾기`는 `사용할 기능` 목록에서 제거하는 것으로 해석한다. 설문에서
검색 수요가 가장 높았던 사실은 그대로 유지하므로, 검색 자체는 사용자가 매번 선택하는 부가 기능이 아니라
문서 요약·QnA·버전 확인·보고서 작성의 기반이 되는 채팅 기본 동작으로 둔다.

| 01 | 내부 문서 저장소 등록·수집 | 4 | 1 | 0 | 매일 2, 주 1~3회 2, 미응답 1 | P0 기반 |
| 02 | 키워드 기반 단순 검색 | 5 | 0 | 0 | 매일 4, 주 1~3회 1 | **P0 최우선 사용자 기능** |
| 03 | 문서 기반 Q&A | 5 | 0 | 0 | 매일 3, 주 1~3회 2 | P0 |
| 04 | 문서 요약 | 5 | 0 | 0 | 매일 3, 주 1~3회 2 | P0 |
| 05 | 최신본·구버전 구분 | 5 | 0 | 0 | 매일 2, 주 1~3회 2, 사용 안 함/미정 1 | P0 정확성 조건 |
| 06 | 부서·사용자별 접근 범위 | 4 | 1 | 0 | 주 1~3회 3, 기타 1, 사용 안 함/미정 1 | P1, 실제 문서 연결 전 필수 |
| 07 | SOP·업무기준 검색 | 4 | 1 | 0 | 주 1~3회 1, 기타 2, 사용 안 함/미정 2 | P1 |
| 08 | 보고서 작성 자동화 | 4 | 0 | 1 | 주 1~3회 2, 기타 1, 사용 안 함/미정 2 | P2 |
| 09 | 개인별 업무 스타일 | 3 | 1 | 1 | 매일 1, 주 1~3회 2, 사용 안 함/미정 2 | P2 |

### 4.2 추천 구현 순서

설문 수요와 기술 의존성을 함께 고려하면 다음 순서가 적절하다.

1. **수집·인덱싱 기반**  
   SMB 읽기, 증분 수집, 파일 메타데이터와 문서 위치 인덱스를 먼저 만든다. 요청마다 SMB를 전체 순회하지 않고
   미리 준비한 인덱스에서 검색한다.
2. **키워드 검색 수직 슬라이스**  
   검색어, 상위 N개 결과, 파일명, 경로, 문서 내 위치, 최신본 여부를 한 번에 반환한다.
3. **근거 기반 Q&A와 문서 요약**  
   검색 결과를 근거로 답하고, 기본 화면은 `핵심 요약 → 상세 설명 → 근거 문서` 순서로 구성한다.
4. **버전 판별과 출처 표시**  
   최신본 후보를 우선 검색하고 답변에 버전 판단 근거를 표시한다. 충돌하면 최신본이라고 단정하지 않고 사용자에게
   확인을 요청한다.
5. **SOP 특화 검색과 관련 문서 추천**  
   기본 검색·Q&A가 안정된 뒤 문서 유형 필터, SOP 전용 결과 표시, 연관 운영 가이드·과거 사례 추천을 추가한다.
6. **보고서 자동화와 개인화**  
   검색·근거·버전 계약이 안정된 다음, 선택한 결과를 정해진 양식으로 변환하는 흐름과 개인별 출력 스타일을 추가한다.

접근 범위 기능은 사용 빈도만 보면 검색보다 낮지만, 실제 문서를 다루는 운영 단계에서는 선택 기능이 아니라
**출시 전제 조건**이다. 현재 합성 데이터 전용 기능 테스트에는 런타임 차단 흐름을 추가하지 않고 별도 운영 준비
트랙으로 관리한다.

## 5. 파일 포맷 구현 우선순위

### 5.1 설문 집계

| 단계 | 포맷 | 필수 응답 | 나머지 응답 | 판단 |
|---|---|---:|---|---|
| 1차 | PPT / PPTX | 5/5 | 없음 | 최우선 |
| 1차 | XLS / XLSX | 5/5 | 없음 | 최우선 |
| 1차 | TXT / MD | 5/5 | 없음 | 최우선 |
| 2차 | PDF | 4/5 | 미응답·미선택 1 | 높은 우선순위 |
| 2차 | DOC / DOCX | 4/5 | 미응답·미선택 1 | 높은 우선순위 |
| 2차 | CSV / TSV | 4/5 | 보류 1 | 높은 우선순위 |
| 3차 | 스캔 PDF / 이미지 PDF | 3/5 | 미응답·미선택 2 | OCR 단계 |
| 3차 | JPG / PNG | 3/5 | 보류 2 | OCR·이미지 이해 단계 |
| 4차 | HWP / HWPX | 0/5 | 보류 2, 불필요 1, 미응답·미선택 2 | 실제 파일 재고 확인 후 |

### 5.2 실제 개발 착수 순서

설문은 구형 바이너리와 최신 OOXML 확장자를 한 항목으로 묶었으므로 `.ppt`와 `.pptx`, `.xls`와 `.xlsx`,
`.doc`와 `.docx`의 수요를 구분할 수 없다. 구현은 다음처럼 최신 포맷을 먼저 지원하는 것을 추천한다.

1. **TXT/MD**: 텍스트 추출·청킹·검색 계약의 기준 구현과 빠른 smoke test에 사용한다.
2. **XLSX와 PPTX**: 5명 모두 필수다. 시트·슬라이드 경계, 표, 이미지 위치, 수식 또는 표시값을 함께 보존한다.
3. **텍스트 PDF, DOCX, CSV/TSV**: 두 번째 묶음으로 추가한다. PDF는 페이지, DOCX는 문단·표,
   CSV/TSV는 행·열 위치를 근거 위치로 반환한다.
4. **스캔 PDF와 JPG/PNG**: OCR을 별도 단계로 추가하고 OCR 여부와 신뢰도를 결과에 표시한다.
5. **PPT, XLS, DOC와 HWP/HWPX**: 실제 공유폴더 확장자 재고를 집계한 뒤 직접 파서 또는 사전 변환 방식을 정한다.

포맷 수요만큼 중요한 사실은 문서 내부 구조다.

| 구조 | 선택 수 |
|---|---:|
| 표 | 5/5 |
| 이미지·도식 | 5/5 |
| 여러 시트·슬라이드 | 5/5 |
| 차트·그래프 | 4/5 |
| 텍스트 | 4/5 |
| Excel 수식 | 3/5 |

따라서 모든 파일을 평문 하나로만 변환하면 요구를 충족하기 어렵다. 최소한 `파일 → 페이지/시트/슬라이드 → 블록`
계층과 표 구조를 보존해야 한다. 이미지·도식은 초기에는 위치와 주변 설명을 보존하고, OCR·이미지 이해는 별도
지연 예산으로 분리하는 편이 안전하다.

## 6. 우선 대상 문서와 사용 흐름

### 6.1 대표 문서 유형

| 순위 | 문서 유형 | 선택 수 |
|---:|---|---:|
| 1 | 회의록·의사결정 문서 | 5/5 |
| 2 | 교육자료·발표자료 | 4/5 |
| 3 | 연구계획서·결과보고서 | 3/5 |
| 4 | SOP·표준작업지침 | 2/5 |
| 4 | 업무 지침서·매뉴얼 | 2/5 |
| 4 | 관리대장·목록 | 2/5 |
| 4 | 기술문서·Wiki | 2/5 |
| 8 | 검사 기준·기준표 | 1/5 |
| 8 | QC 관련 문서 | 1/5 |

첫 합성 fixture와 시나리오는 회의록, 발표자료, 연구 문서를 중심으로 만드는 것이 설문에 가장 가깝다. 실제 환자,
검사, 보고서 형식과 닮은 예시는 사용하지 않는다.

### 6.2 대표 사용 흐름

자유서술 응답은 다음 흐름으로 묶인다.

```text
질문 입력
  → 관련 문서 검색
  → 문서 안의 근거 위치 표시
  → 핵심 요약과 상세 답변
  → 여러 문서·버전 비교
  → 사용자가 선택하면 보고서 또는 기안 초안 생성
```

추가 요청으로는 한 질문에 답하는 데서 끝내지 않고 운영 가이드, 장애 대응 매뉴얼, 설정 문서, 과거 사례 같은
연관 문서를 함께 추천해 달라는 의견이 1건 있었다. 유용한 확장 기능이지만 핵심 검색 품질을 먼저 검증한 뒤
추가하는 것이 적절하다.

## 7. 답변 화면과 실패 동작

### 7.1 선호 답변 형태

| 답변 요소 | 선택 수 | 기본 적용 |
|---|---:|---|
| 핵심 요약 + 상세 설명 | 5/5 | 항상 표시 |
| 문서별 요약 | 3/5 | 여러 문서가 검색될 때 |
| 단계별 업무 절차 | 3/5 | 절차·SOP 질문일 때 |
| 원문 링크·경로 | 3/5 | 근거마다 표시 |
| 정해진 보고서 양식 | 2/5 | 후속 생성 동작 |
| 표 형식 비교 | 1/5 | 비교 질문일 때 |
| 관련 문서 목록·미리보기 | 1/5 | 보조 영역 |

권장 기본 응답은 다음 네 부분이다.

1. 한눈에 보는 핵심 요약
2. 상세 설명 또는 단계별 절차
3. 근거 문서의 파일명·경로·페이지/시트/슬라이드 위치
4. 관련 문서와 다음 동작

### 7.2 근거 부족 시 동작

| 기대 동작 | 응답 수 |
|---|---:|
| 추정하지 않고 근거 부족 안내 | 2/5 |
| 질문 범위나 조건 재확인 | 2/5 |
| 가장 관련된 문서 목록만 제시 | 1/5 |

세 응답은 상호 배타적으로 구현할 필요가 없다. 다음 순서로 합치면 모든 기대를 수용할 수 있다.

1. 답을 확정할 근거가 부족하다고 명시한다.
2. 검색된 문서와 확인한 범위를 보여준다.
3. 가장 가까운 문서가 있으면 목록만 제시한다.
4. 기간, 부서, 문서 종류, 버전 등 부족한 조건을 질문한다.

## 8. 버전·갱신 요구

### 8.1 최신본 판단 기준

| 판단 신호 | 언급 수 |
|---|---:|
| 파일명에 포함된 버전 | 4/5 |
| 수정일·업데이트 날짜 | 3/5 |
| 승인일 | 1/5 |
| 담당자 확인 | 1/5 |
| 문서번호·표준 지침 | 1/5 |

최신본은 수정 시각 하나로 단정하지 말고 파일명 버전, 수정일, 승인 메타데이터, 문서번호를 함께 비교해야 한다.
초기 구현은 후보 순위를 계산하되 사용자에게 판정 근거를 보여주고, 신호가 충돌하면 확인 필요 상태로 반환한다.

### 8.2 문서 변경 주기

| 변경 주기 | 응답 수 |
|---|---:|
| 주 2회 | 1/5 |
| 주 단위 | 2/5 |
| 비정기 | 2/5 |

3명은 적어도 주 단위로 문서가 바뀐다고 답했다. 요청 시 전체 SMB를 다시 순회하기보다 증분 인덱스를
백그라운드에서 갱신하고, 비정기 변경을 위한 수동 갱신 동작을 함께 두는 편이 적절하다.

적재·업데이트 관리 화면은 필수 1명, 확인 필요 3명, 현재 불필요 1명으로 합의가 약하다. 초기에는 API·로그로
갱신 상태를 확인하고, 별도 관리 화면은 후순위로 둔다.

## 9. 접근 범위와 운영 전환 항목

역할별 접근 범위는 `필수` 1명, `일부 문서집합만 필요` 3명, `현재는 불필요` 1명이다. 즉 4명은 전부 또는
일부 문서에 범위 구분이 필요하다고 답했다.

다른 부서 문서 검색에 대해서도 무제한 전체 검색을 원한 응답은 없었다.

- 권한이 있으면 전체 검색: 2명
- 질문별 승인·선택 필요: 1명
- 자기 부서 문서만 검색: 1명
- 공통 문서만 부서 간 검색: 1명

민감정보 처리 방식은 가명화·마스킹 2명, 제한 저장소에 원본을 두고 경로만 공유 2명, 확인 필요 1명으로
합의되지 않았다. 따라서 실제 문서를 사용하기 전에 다음을 별도 결정해야 한다.

1. 문서·폴더별 권한의 기준과 권한 원본
2. 검색 결과, 답변, trace에 노출해도 되는 경로 수준
3. 원문을 처리하는 모델의 위치와 외부 전송 금지 범위
4. 마스킹과 제한 저장소 방식 중 적용할 정책

현재 저장소의 합성 데이터 전용 단계에서는 이 결정을 임의 구현하지 않는다. 다만 실제 SMB 연결 전에는
접근 범위 필터가 검색·Q&A·요약·버전 비교 전 경로에 동일하게 적용되는지 검증해야 한다.

## 10. 다음 조사에서 보완할 항목

운영 범위를 확정하기 전에 다음 조사를 추가하는 것이 좋다.

1. 분자유전팀 등 실제 사용 부서의 역할별 응답 확보
2. 실제 파일 내용이 아닌 확장자별 파일 수·크기·갱신 빈도 통계 확보
3. `.ppt`와 `.pptx`, `.xls`와 `.xlsx`, `.doc`와 `.docx` 수요 분리
4. “필수이지만 사용 안 함/미정” 응답의 의미 재확인
5. 최신 승인본을 결정하는 공식 규칙과 문서번호 체계 확인
6. 답변에 표시 가능한 파일 경로 수준과 부서 간 검색 승인 절차 확정

이 보완 조사가 끝나기 전까지는 본 문서의 P0을 합성 데이터 기능 검증 범위로 사용하고, P1 운영 항목은 정책과
실제 파일 재고가 확인된 뒤 확정한다.
